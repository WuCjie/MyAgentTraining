# 使用本地嵌入模型做文本向量化

## 1. 概述

文本向量化（Embedding）是将文本转化为固定维度向量矩阵的过程，是 RAG（检索增强生成）系统的核心环节。本文记录使用本地部署的 **Qwen3-Embedding-0.6B** 模型完成文本向量化的完整流程和踩坑记录。

## 2. 环境准备

### 2.1 模型下载

从 ModelScope/HuggingFace 下载 Qwen3-Embedding-0.6B 模型到本地目录。模型文件结构：

```
Qwen3-Embedding-0.6B/
├── model.safetensors          # 模型权重 (1.2GB)
├── tokenizer.json             # 分词器
├── vocab.json                 # 词表
├── merges.txt                 # BPE 合并规则
├── config.json                # 模型架构配置
├── tokenizer_config.json      # 分词器配置
├── config_sentence_transformers.json  # SentenceTransformer 配置
├── modules.json               # 流水线模块定义
├── 1_Pooling/config.json      # 池化策略
└── 2_Normalize/config.json    # 归一化层
```

### 2.2 依赖安装

```bash
pip install sentence-transformers
```

`sentence-transformers` 会自动安装 `transformers`、`torch` 等依赖。

## 3. 模型加载与使用

### 3.1 正确方式：使用 SentenceTransformer

Qwen3-Embedding 是 SentenceTransformers 格式的模型，内部由三个模块组成流水线：

```
Transformer (Qwen3) → Pooling (last token) → Normalize (L2)
```

加载代码：

```python
from sentence_transformers import SentenceTransformer

model_path = r"C:\path\to\Qwen3-Embedding-0.6B"
model = SentenceTransformer(model_path)

# 编码文本，返回归一化后的向量
texts = ["洛洛是机战王", "路飞是要成为海贼王的男人", "今天天气真好"]
embeddings = model.encode(texts, normalize_embeddings=True)

print(embeddings.shape)  # (3, 1024)
```

### 3.2 计算语义相似度

```python
import numpy as np

def cosine_similarity(a, b):
    return np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b))

emb1 = model.encode("洛洛是机战王", normalize_embeddings=True)
emb2 = model.encode("洛洛操控机车战士", normalize_embeddings=True)
emb3 = model.encode("今天吃了苹果", normalize_embeddings=True)

print(f"相关文本相似度: {cosine_similarity(emb1, emb2):.4f}")   # 0.44
print(f"无关文本相似度: {cosine_similarity(emb1, emb3):.4f}")   # 0.26
```

## 4. 踩坑记录

### 4.1 坑一：Unicode 转义错误

**现象**：

```
SyntaxError: (unicode error) 'unicodeescape' codec can't decode bytes...
```

**原因**：docstring 中写了 Windows 路径 `C:\Users\...`，`\U` 被 Python 解释为 Unicode 转义序列（`\Uxxxxxxxx`），但 `sers` 不是合法的 8 位十六进制字符。

**修复**：docstring 中的路径使用正斜杠 `C:/Users/...`，或给字符串加 `r` 前缀。注意：代码中的路径变量 `model_path` 始终用 raw string `r"..."`。

### 4.2 坑二：模型下载不完整

**现象**：`modules.json` 定义了 `2_Normalize` 模块，但 `2_Normalize/` 目录不存在。

**原因**：下载过程中断或工具版本问题导致归一化层配置文件未下载。

**修复**：手动创建 `2_Normalize/config.json`（内容为 `{}`，SentenceTransformer 会自动初始化为 L2 归一化）。

### 4.3 坑三：用 AutoModel 加载 SentenceTransformers 模型

**现象**：模型能加载但向量质量差，语义相似度接近随机。

**原因**：

- `AutoModel.from_pretrained()` 只加载原始 Transformer，跳过了 Pooling 和 Normalize 模块
- Qwen3 是 decoder-only 架构，`last_hidden_state[:, 0, :]` 取第一个 token 不适合做句子表征
- 缺少 L2 归一化，导致相似度计算不准确

**修复**：使用 `SentenceTransformer` 加载，它会自动组装完整的 Transformer → Pooling → Normalize 流水线，`encode()` 返回的向量直接可用于相似度计算。

### 4.4 坑四：Jupyter kernel 状态污染 —— NameError: name 'nn' is not defined

**现象**：

```
NameError: name 'nn' is not defined
```

报错定位指向模型加载内部代码，但命令行运行同样的代码却正常。

**原因**：之前的 `SyntaxError`（坑一）虽然阻止了代码执行，但 Jupyter kernel（或 PyCharm 的 notebook runner）在解析失败后可能残留了异常的模块导入缓存。后续即使修复了代码，kernel 仍处于被污染的状态，导致 transformers 内部对 `torch.nn` 的引用出现混乱。

**修复**：

- **PyCharm**：重启 PyCharm（关闭重新打开），或菜单栏 Run → Restart Kernel
- **Jupyter**：Kernel → Restart Kernel
- 重启后重新运行单元格即可

> 此问题本质上不是代码错误，而是 notebook 运行环境的缓存污染。遇到类似"代码语法改了依然报奇怪的运行时错误"时，优先重启 kernel。

### 4.5 坑五：多余的 trust_remote_code

**现象**：加上 `trust_remote_code=True` 后反而可能触发不必要的远程代码检查或下载。

**原因**：模型的 `config.json` 中没有 `auto_map` 字段，说明模型完全使用 `transformers` 内置的 `Qwen3ForCausalLM`，不存在需要信任的自定义代码。加上这个参数不仅多余，在某些网络环境下还可能因尝试连接 HuggingFace Hub 而卡住。

**修复**：去掉 `trust_remote_code=True`，直接 `SentenceTransformer(model_path)`。

### 4.6 总结：SentenceTransformer vs AutoModel

| 对比维度 | SentenceTransformer | AutoModel |
|---------|-------------------|-----------|
| 池化策略 | 自动（last token pooling） | 需手动实现 |
| 向量归一化 | 自动 L2 归一化 | 需手动实现 |
| 编码接口 | `model.encode(texts)` 一行搞定 | 需 tokenize → forward → pooling → normalize |
| 适用场景 | 嵌入模型（本文场景） | 底层模型调试/自定义流水线 |

## 5. 在 RAG 中的应用

配合文本分割器使用：

```python
from langchain_community.document_loaders import TextLoader
from langchain_text_splitters import RecursiveCharacterTextSplitter
from sentence_transformers import SentenceTransformer

# 1. 文档加载与切分
loader = TextLoader("document.txt", encoding="utf-8")
documents = loader.load()

text_splitter = RecursiveCharacterTextSplitter(
    chunk_size=500,
    chunk_overlap=50,
)
chunks = text_splitter.split_documents(documents)

# 2. 向量化
model = SentenceTransformer(model_path)
chunk_texts = [chunk.page_content for chunk in chunks]
chunk_embeddings = model.encode(chunk_texts, normalize_embeddings=True)

# 3. 检索时，将 query 向量化后与 chunk_embeddings 做相似度匹配
query = "洛洛是谁？"
query_embedding = model.encode(query, normalize_embeddings=True)
```

## 6. 关键要点

1. **SentenceTransformer 格式的模型必须用 `SentenceTransformer` 加载**，不能用 `AutoModel`。
2. Windows 路径含 `\U`、`\n`、`\t` 等字符时，**非 raw string 会触发转义错误**，路径变量统一使用 `r"..."`。
3. 下载模型后检查 **`modules.json`** 中引用的所有模块目录是否齐全。
4. Qwen3-Embedding 使用 **last token pooling** 策略（在序列末尾取向量），这是其官方推荐的池化方式。
5. **模型没有 `auto_map` 时不需要 `trust_remote_code=True`**，加了反而可能引发额外问题。
6. **Notebook kernel 缓存污染**会制造假错误——改了代码还报错时，先重启 kernel。
